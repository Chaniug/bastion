# Bastion 守卫测试（Guard Test）写法规范

> **目的**：固化 B.2.3「守卫测试脆弱性治理」沉淀下来的写法纪律，让**新增守卫**
> 不再复现"精确子串匹配 → 无害重构即假失败"的问题，同时**不丢失回归信号**。
>
> **适用范围**：所有使用 `projectFile(...).readText()` 读取源码/资源、再做 `.contains(...)`
> 断言的回归守卫测试（`*RegressionGuardTest.kt`、`*GuardTest.kt`）。
>
> **生效**：本文档经 B.2.3 治理后确立，新守卫须遵守；存量守卫按 Wave 节奏逐步收敛。

---

## 一、核心原则

守卫测试的价值是**防止架构回退**。它有两种实现路径，优先级从高到低：

1. **运行时行为验证（最稳）**：直接调用 API / 构造对象，断言返回值或副作用。
2. **源码文本匹配（次稳，但有脆性）**：必须看源码结构时才用，**且必须容错**。

> ❌ 禁止：为了"不报错"删除守卫，或把断言弱化到无回归信号。
> ❌ 禁止：改动被守卫保护的主代码语义（本文档只管测试写法，不动业务）。

---

## 二、三档处理策略（Tier）

| 档位 | 适用场景 | 做法 | 风险 |
| --- | --- | --- | --- |
| **Tier A：转行为测试** | 被守卫的类可纯 JVM 单测（如 `KeePassOperationAvailability`、`AutofillLogger` 等已验证可行） | 删掉 `readText`，直接调用 API 断言行为 | 最低 |
| **Tier B：正则容错** | 必须看源码文本，但匹配的是"结构/关键字"而非"字面格式" | 精确 `contains("...")` → `Regex(...)` 容忍空白/换行/属性顺序/局部重命名，**保留 ≥1 个稳定语义锚点 token** | 低（锚点守住信号） |
| **Tier C：保留但文档化** | 断言的是"禁止某调用"（如 `不得 runBlocking` / `不得 JSON.decodeFromString<TotpData>`） | 保留精确 token，加注释说明为何必须精确 | 零（本就是意图守卫） |

### 锚点原则（Tier B 的铁律）

任何 B 档正则都必须保留至少一个**语义锚点**——即只有真实回归才会消失的 token
（方法名、关键异常类、被禁止的 API 名、敏感变量锚点 `${...}`）。正则只容忍"环绕它的格式噪声"。

```
坏例子（无锚点，过松会被绕过）：
    Regex("\\s*=\\s*")          // 任何赋值都命中，毫无回归信号

好例子（保留方法名锚点，只容忍空白）：
    Regex("totpViewModel\\.savePasswordBoundTotps\\s*\\(")
```

## 三、Tier B 正则模板（可直接抄）

| 脆弱来源 | 原精确写法 | 容错正则（保留锚点） |
| --- | --- | --- |
| `=` 两侧空白/换行 | `"x = y"` | `Regex("x\\s*=\\s*y")` |
| `=` 与 `+` 混合漂移 | `"a = b + c"` | `Regex("a\\s*=\\s*b\\s*\\+\\s*c")` |
| `if (cond)` 拆行 | `"if (x) {"` | `Regex("if\\s*\\(\\s*x\\s*\\)\\s*\\{")` |
| 日志/错误消息半角↔全角冒号 | `"key:value"` | `Regex("key\\s*[:：]\\s*value")` |
| 局部变量重命名 | `"val oldName = ..."` | 保留稳定方法名锚点，重命名部分用 `\\w+` 或省略 |
| XML 属性顺序 | `<View a="1" b="2"/>` | `Regex("a=\"1\"").*Regex("b=\"2\"")` 或顺序无关的两段匹配 |
| 方法调用换行 | `"foo(a, b)"` | `Regex("foo\\(\\s*a\\s*,\\s*b\\s*\\)")` |
| 代码片段/override | `"override fun onX()"` | `Regex("override\\s+fun\\s+onX\\s*\\(\\s*\\)")` |

> 位置相关的排序断言（如 `indexOf` 比较）**保留精确**，不要正则化——顺序本身就是要保护的语义。

## 四、Kotlin 字符串转义陷阱（CI 血泪总结）

正则写在 Kotlin 字符串字面量里，转义要过两关：**Kotlin 字符串转义** 和 **正则转义**。

### 4.1 字面 `$` 的转义

源码里 `File(foldersRootDir, "$folderKey/...")` 的 `$folderKey` 无花括号。测试要让正则匹配**字面 `$`**，必须写成：

```
\\\$folderKey      // Kotlin: \\ → \ , \$ → $  ⇒ 正则 \$folderKey（$ 被转义不当模板）
```

- 写成 `\\$folderKey`（两反斜杠）会被 Kotlin 当 `$folderKey` 模板变量 → 编译失败 `Unresolved reference 'folderKey'`。
- 花括号形式 `${...}` 在测试里写成 `\\$\\{...\\}`（已多次 CI 验证安全）。

### 4.2 校验器必须忠实复刻 Kotlin 转义

早期用非贪婪 `"..."` 提取正则，遇到体内嵌转义引号 `\"` 会截断提取 → 部分断言被静默跳过而误报"全绿"。
提取正则体时必须做 `\\`→`\`、`\"`→`"`、`\$`→`$` 的 **unescape**，并按"未被 `\` 转义的引号"作为串边界。

### 4.3 预检脚本拦截裸模板写法

推送前用 Python 脚本扫 `Regex("...")` 内部，标记"偶数反斜杠 + `$` 后接标识符"的真·裸模板写法
（即忘了转义 `$` 的写法），在推送前拦截，避免 CI 编译失败。

## 五、提交纪律（与 CI 协同）

- 每条断言改动后，用 Python `re` **预校验**：忠实复刻 Kotlin 转义 → 编译正则 → 匹配**原串** → 匹配**常见变体**（加空行/重排参数/全半角冒号）。
- 原串必须仍命中（证明没削弱牙齿）；变体命中证明容错有效。
- 改完 → `git push dev` → 看 GitHub Actions（`BASELINE_FAILURES` 只降不升）。
- **良性重构探针**：在某波用一个临时"良性重构"提交（如给某方法体加一行空行/重排参数）确认守卫仍绿，再 revert——避免"看起来改了但并没更稳"的假象。
- 每波 ≤ ~8 文件、小提交、推 CI 观察；不一次性大改 47 个文件（风险高、难 review、CI 噪音大）。

## 六、新增守卫检查清单

- [ ] 能转行为测试（Tier A）吗？能 → 直接做，删 `readText`。
- [ ] 必须看源码？→ 用 `Regex(...)` 而非精确 `contains("...")`。
- [ ] 正则保留 ≥1 个语义锚点 token？（无锚点 = 不达标，打回）
- [ ] 字面 `$` 正确转义为 `\\\$`？花括号 `${...}` 转义为 `\\$\\{...\\}`？
- [ ] 用 Python 预校验：原串命中 + 常见变体命中？
- [ ] 位置/顺序类断言保持精确？
- [ ] 推 `dev` 后 CI `failed=0`？

---

## 七、红线（绝不妥协）

- ❌ 删除守卫或弱化到无回归信号，只为"让 CI 绿"。
- ❌ 正则过松丢失锚点（见 §二 锚点原则）。
- ❌ 改动被守卫保护的主代码语义来"适配"测试。
- ❌ 一次性大改全部 47 个守卫文件。
