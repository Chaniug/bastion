# 开发者设置冗余功能清理记录（接力文档）

> 分支：`dev` → 验收通过后合 `main`
> 设备背景：用户真机为 **荣耀 MagicOS / Android 17**
> 状态：**代码清理已完成，待 dev 分支 CI 验收通过后合 main**

---

## 1. 背景与关键判定

用户发来开发者设置页截图，问"哪些功能是我不需要的"。盘点后确认：开发者设置里大部分开关是调试/取证/厂商兼容用途，对普通用户（且是荣耀而非小米）属于冗余甚至**死逻辑**。

关键纠正（用户明确指出）：

> **HyperOS 是小米系统，荣耀用的是 MagicOS。**

因此 "Passkey HyperOS 兼容" 开关在荣耀上是**死开关**：其生效条件为 `isBypassEnabled && romType == HYPER_OS && hasHyperOsSystemPropertyPresent()`，荣耀设备 `romType` 永远不是 `HYPER_OS`，第一关即失败，开关无论怎么设置都不生效。该开关应清理，而不是保留。

## 2. 清理范围

### 已移除（8 项开发者设置功能 + 配套底层代码）

| 功能 | 类型 | 移除理由 |
| --- | --- | --- |
| 关闭密码验证（`developer_disable_password_verification`） | DEBUG 开关 | 仅开发测试，破坏主密码保护，是死开关（受 `BuildConfig.DEBUG` 限制） |
| Passkey HyperOS 兼容（`developer_passkey_hyperos_biometric_bypass`） | 厂商兼容 | 小米 HyperOS 专属，荣耀为 MagicOS，永不成立 → 死开关 |
| 启用 Bitwarden 同步取证（`developer_bitwarden_forensics_toggle`） | 取证 | 调试取证，普通用户无需 |
| 记录 Bitwarden 原始请求/响应（`developer_bitwarden_forensics_raw_toggle`） | 取证 | 同上 |
| 取证输出目录（`developer_bitwarden_forensics_dir` + 选择/清除） | 取证 | 同上 |
| 自动填充调试（`developer_autofill_debug` + V2 测试入口 + 会话状态 DEBUG） | 调试入口 | 调试用，普通用户无需 |

配套删除/去耦的底层代码：
- `BitwardenSyncForensicsLogger.kt`（整文件删除，720 行）
- `PasskeyBiometricCompatibilityPolicy.kt`（整文件删除）
- `BitwardenSyncService` / `CipherSyncProcessor` / `CipherUploadProcessor` 中的取证采集调用（条件包裹，直接删除；`captureRawExchange` 私有方法保留签名、置为 no-op，避免改动 10+ 处上传/同步调用点）
- `PasskeyAuthActivity` / `PasskeyCreateActivity` 的生物识别 bypass 分支
- `MainAppLockPolicy.resolveAccessState` 的 `disablePasswordVerification` 参数与跳过分支
- `AppSettings` / `SettingsManager` / `SettingsViewModel` 中对应字段与 key
- `PasskeyValidationFlags` 的 `KEY_HYPEROS_BIOMETRIC_BYPASS_ENABLED`
- 两个源码字符串守卫生测试（`MultiPasswordSaveRegressionGuardTest` 中两条 forensics 断言，因被保护代码已删除而失效）
- `PasskeyBiometricCompatibilityPolicyTest.kt`（整文件删除）

### 保留（4 项，普通用户/调试仍有价值）

- 日志调试组：查看日志 / 清除日志缓冲 / 分享日志
- 主应用名称切换（`developer_launcher_name_use_pass`，launcher 入口名称）

## 4. 兼容性残留说明（留给后续 agent）

- `utils/DeviceUtils.kt` 仍保留 `ROMType.HYPER_OS`、`isHyperOS()`、`isHyperOsSystemPropertyPresent()` 等通用设备检测能力。本次未删除——它们是通用 ROM 识别，且被其他可能的动画/兼容逻辑引用，超出"开发者设置清理"范围。若后续确认无调用方，可单独清理。
- `captureRawExchange` 在两处上传/同步服务中保留为 no-op 空方法（保留签名以最小化改动面）。若未来想彻底移除调用点，需同步清理 `BitwardenSyncService`（约 10 处）与 `CipherUploadProcessor`（约 17 处）的调用点，再删除方法。
- DataStore 中可能残存旧 key 的存储值（`disablePasswordVerification` 等），新版本读取已不引用，无需迁移。
