# 安卓端预览功能整合 + 首页分割线清理

> 实机反馈修复（荣耀 安卓 17）。关联提交：dev 分支 `style(android): 移除分类文件夹 Tab 中"新建分类"按钮上方分割线` 与 `refactor(android): 预览功能整合（毕业 2 项、移除减少动画、新增 KeePass DX 引擎）`。

## 1. 三件事的最终方案

### 1.1 首页分类文件夹 Tab 的分割线 → 移除
- **问题**：图 1 中"Pass"分类 chip 与"新建分类"按钮之间有一条浅灰 `HorizontalDivider`，在分类为空时孤悬，视觉突兀。
- **根因**：`PasswordCategoryActionButtons.kt:42` 的 `HorizontalDivider` 无条件渲染，与 chip 列表是否为空无关；只要该 Tab 选中且有可用操作就画。
- **修复**：删除该 `HorizontalDivider`（连同不再使用的 `HorizontalDivider` / `padding` import）。父容器 `PasswordListCategoryChipMenu` 已是 `Column(spacedBy(16.dp))`，删除后按钮不会粘连。
- **影响面**：该组件被 `PasswordListCategoryChipMenuBottomActions` 与 `CategoryManagementState.CategoryManagementTrailingContent` 复用，统一移除。

### 1.3 "减少动画"是死开关，整套移除
- **证据链**：
  - `MainActivity.kt:935-941` 硬编码 `CompositionLocalProvider(LocalReduceAnimations provides true, LocalSharedTransitionScope provides null)`
  - `PasswordEntryCard.kt:66,69` 读取 `LocalReduceAnimations.current` 作为 `!reduceAnimations` 判断，但全局永远为 `true` → `!reduceAnimations` 永远 `false` → `sharedBounds` 永不执行
  - 设置项 `settings.reduceAnimations` 在整个 `ui` 包只被"预览 UI 读取"，从未驱动 `LocalReduceAnimations`
- **移除范围**：
  - `AppSettings.kt` 删除 `reduceAnimations` 字段
  - `SettingsManager.kt` 删除 `REDUCE_ANIMATIONS_KEY` 定义 + 读取 + `updateReduceAnimations(...)`
  - `SettingsViewModel.kt` 删除 `updateReduceAnimations(...)`
  - `SettingsScreen.kt` 删除预览对话框中的 Row UI
  - `values/strings.xml` 与 `values-zh/strings.xml` 删除 `reduce_animations` / `reduce_animations_description`
- **保留不动（合理的详情页 safe mode）**：`LocalReduceAnimations` 定义、`MainActivity` 与 `PasswordTabPane.kt:239-242` 的硬编码 —— 详情屏 `enableSharedBounds=false` + `LocalSharedTransitionScope provides null` 是规避 "Placement happened before lookahead" 崩溃的有意设计，本轮不拆。

## 2. "共享元素动画总开关"为什么被跳过（重要）
用户最初同意"新增共享元素动画总开关（替代死掉的减少动画）"，但勘察发现一个**阻断性事实**：

> 应用内**没有任何 `SharedTransitionLayout(...)` 调用**（全工程 grep 零命中）。只有 `MainActivity` 的硬编码 `LocalSharedTransitionScope provides null`。

这意味着即使新加"共享元素动画总开关"、接入 `CompositionLocalProvider`，由于没人包装 `SharedTransitionLayout`，`PasswordEntryCard` 读到的 `sharedTransitionScope` 永远是 `null`，开关**仍会是新的死开关**。

要让该开关真正生效，需要独立的中等工作量改动：
1. 在 `SimpleMainScreen`（或更高层）包一个 `SharedTransitionLayout`
2. 移除 `MainActivity` / `PasswordTabPane` 的硬编码 `LocalSharedTransitionScope provides null`
3. 把开关接入 `CompositionLocalProvider`，按设置提供真实 scope
4. 处理 `PasswordTabPane.kt:239-242` 详情屏的 `enableSharedBounds=false` 与 `LocalAnimatedVisibilityScope provides null`

⚠️ 原始注释明示全量禁用共享动画是为了规避 **"Placement happened before lookahead"** 崩溃（Compose `ExperimentalSharedTransitionApi` 的框架级 lookahead bug），重新启用有风险。**建议作为独立议题推进**，不在本次实机问题修复范围。
